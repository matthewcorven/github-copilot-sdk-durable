### `duplicate-delivery`

| --- | --- | --- | --- |

What that costs is also in the record: a refused run does nothing and does not queue, so a delivery that means to wait has to retry, and the refusal is per store file rather than per repository. |

No process detected the other: Phase 8 reads its parent at Phase 8, so the compare-and-swap only ever sees the write immediately before it, and the second writer's state replaced the first's with no error. ### `store-outage`

| Variant | Outcome | Phase | Detail |
| --- | --- | --- | --- |
| baseline | **failed loudly, effects kept, state lost** | after Phase 7's outputs exist, before Phase 8 commits; repo.git moved aside | repo.git was moved aside after Phase 7 had written its outputs and while Phase 8 was about to commit. Phase 8's git call ran against a path that no longer named a repository and the run failed with exit 1 (baseline: git failed: git hash-object -w --stdin: error: unable to create temporary file: No such file or directory ). The effects are on disk — 13 comment(s), labels.json, the report — and the state is gone: no memory/pr-triage branch in the moved repository (0 commit(s) on it, state 'none'), and the path itself no longer exists. That is failing loudly and it is also the reason the baseline is in this band: the outage is discovered, but only after the comments were posted, and what it costs is exactly the cooldown-desync window. |
| durable | **failed safely, with a split store** | in flight (Phase 1 committed, Phase 2 running); the store file moved aside | The store file was moved aside while the run held its handle. The process did not fail: exit 0, final phase 'save run state', 13 comment(s) posted, and it recreated the path, so the live store now holds 'save' with its own history while the moved file still holds the committed prefix it had at the outage ('classify', 7667 bytes, 1 generation(s) of state, triage list []). Nothing that was committed was lost — every record in the moved file is readable and the run record it holds is the one that was committed — but the state is now in two files, and an operator reading the live path is reading a history that never existed while the run was alive. The application fails safe in the sense that it reports no corruption and keeps running; it does not fail loudly, and it does not tell anyone the file it was writing had gone. |
