=== three real defects this run found, all fixed ===
1. Duplicate manager tore down the live connection.
   The app created a SECOND FoundryBridge purely to inspect state. Foundry Local Core
   initializes once per service process, so the second creation logged
   "FoundryLocalCore has already been initialized" (17 times) and dropped the connection
   that the real call was using. Removed: the transport now reports progress through a
   Diagnostic event instead of opening a second manager.

2. download() reports Failure when there is nothing to download.
   Service log: "Blob enumeration complete: 0 to download, 6 skipped",
   "totalSizeToDownload:0 totalSizeAlreadyDownloaded:2777051903", then
   "Command:ModelDownload Status:Failure". Neither the download status nor isCached() was
   trustworthy in that state, so the facade now treats download as best-effort and lets
   load() decide whether the model is usable. After that change the same model loaded:
   "Model loaded successfully".

3. phi-3.5-mini kills the service process on this device.
   Reaching chat_completions with phi-3.5-mini produced
   "Service process gone during FoundryChatCompletionClient.completeChat" and the service
   restarted under a new pid, before any answer arrived. qwen2.5-0.5b completes normally on
   the same code path and the same device. This is a behaviour of the preview service app
   with that model here, recorded rather than worked around.
