Band E / issue #166 — a larger model on the emulator: does the emulator constrain the choice?
Captured 2026-11-25. Transcribed from commands run against the booted AVD; output quoted, not
paraphrased.

The issue's note says: "If the emulator cannot run the model acceptably, record the measurement and
use a physical device — do not quietly swap to a smaller model and report different numbers."

The committed default is qwen2.5-0.5b. That swap was declared, but the condition behind it was never
tested: no larger model had been tried on the emulator. This file tests it.

=== what this establishes, and what it does not ===

Establishes: the emulator can load and run qwen2.5-1.5b, with the network off, through the whole
demonstration including a kill and reopen. The emulator is therefore NOT the constraint that forced
a 0.5B model. The issue's condition for the swap cannot be satisfied by claiming an emulator limit.

Does not establish: that 1.5B is the better default. It is 4-8x slower per turn on this emulator
(32.9-56.5 s against 2.9-3.7 s for 0.5B on the physical device), and it trips the document size
guard on two of the three edit turns, because it replies with a short summary of the change rather
than the whole document. See "the guard" below.

=== the guard, and what the 1.5B replies exposed ===

The demonstration asks for "a document the agent edits across turns". Turns 2 and 3 of this run did
not change the document:

  reply was 303 chars against a 1384-char document: kept the document
  reply was 673 chars against a 1384-char document: kept the document

That is Demo's size guard working as designed: a reply shorter than half the previous document is
treated as a collapsed response and refused, a defect E2 fixed after a one-line reply overwrote the
document. But with a more capable model the guard is now rejecting something else: a correct,
surgical answer. The 1.5B model reads "add a section" and returns the section plus a line of
context, which is what the instruction asks for; it is the *whole-document rewrite* that satisfies
the guard, and that is a 0.5B behaviour.

So the guard conflates "the model collapsed" with "the model edited surgically". Recording it here
rather than tuning it away: it is a real interaction between a durability safety rule and model
capability, and variant 1's demonstration is written around whole-document rewrites.
