The bridge behaves identically on real hardware and on the emulator: the Kotlin class loads,
start() runs, FoundryLocalManager.create throws because there is no service to bind to, and the
exception crosses the generated invoker into a classified ChatFailureKind.

No .apk is published. com.microsoft.foundrylocal.app is distributed only through Google Play,
so it cannot be installed by sideload from the release assets. A Play Store sign-in on the device
is required, which only the device owner can perform.

=== a guessed model alias was removed as a blind spot ===
The app previously hard-coded "phi-3.5-mini" and would have failed with an unexplained
"alias not in catalog" if the device catalog disagreed. It now asks the catalog and prints the
aliases it really offers (bridge.listModelAliases -> BridgeShim.ListAliasesAsync -> screen), but
only once the service app is present. This run could not reach that point because start() fails.
