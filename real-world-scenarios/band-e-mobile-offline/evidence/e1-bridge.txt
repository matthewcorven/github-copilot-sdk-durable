The Foundry binary is a `compileOnly` input: the facade is compiled against it but it is not
folded into this AAR. Two reasons, both load-bearing:
  - AGP refuses to build an .aar that contains a local .aar dependency:
      "Direct local .aar file dependencies are not supported when building an AAR"
  - DECISION-bridge.md §5 forbids redistributing the binary anyway.
The app references the same verified file, so the classes exist once, at runtime, in the APK.

=== compiling the facade found the real API ===
The first draft was written from the guide's prose and was wrong in four ways. `javap` against
the actual AAR corrected it, which is why the facade is written against verified signatures:
  - create() is suspend and returns FoundryLocalManager, not a constructor
  - the chat request type is com.microsoft.foundrylocal.api.ChatCompletionRequest
    (there is also a Parcelable datamodels.chat.ChatCompletionRequest; it is not the one ChatClient takes)
  - ChatMessage is (role, content) with ROLE_SYSTEM/ROLE_USER/ROLE_ASSISTANT constants
  - Model.download(progress, contentIntent, timeoutMinutes) has named parameters and defaults
  - FoundryLocalManager.isConnected is a Kotlin property, not a method

=== binding the raw AAR fails, exactly as the decision record predicted ===
Referencing the Foundry AAR as an ordinary AndroidLibrary produced:
  error CS0260: Missing partial modifier on declaration of type 'Catalog'; another partial
                declaration of this type exists
  error CS0579: Duplicate 'Register' attribute
for Catalog, FoundryLocalManager, FoundryModel, FoundryChatCompletionClient,
FoundryAudioTranscriptionClient — the obfuscator-kept synthetic surface §3.2(a) describes.
Resolution: <AndroidLibrary ... Bind="false" /> plus
<AndroidGenerateJavaBindingAnnotations>false</AndroidGenerateJavaBindingAnnotations>.
The Kotlin facade is the binding; no C# metadata is generated from the raw AAR.

=== the JNI boundary actually works, on device ===
Installed and launched on band-e-api36-playstore-arm64 (Android 16, API 36, arm64-v8a).
Tapping "Send turn" produced this on screen:

  "failed [TransportUnavailable] retryable: companion app com.microsoft.foundrylocal.app
   absent — com.microsoft.foundrylocal.app is not installed (API 36)
   bridge loaded; start() failed [TransportUnavailable]:
   FoundryLocalException: Failed to bind to service using explicit intent"

Read that carefully, because it is the point of this capture. The managed code did not guess:
  - the Kotlin `FoundryBridge` class loaded and `start()` ran (JNI call succeeded);
  - it called `FoundryLocalManager.create(...)`, which threw `FoundryLocalException` because
    there is no service app to bind to;
  - that exception crossed the generated invoker into a managed `BridgeException` carrying a
    classified `ChatFailureKind`.
That is the whole cross-language path working. What it cannot do is produce an answer, because
the service it binds to is not installed.
